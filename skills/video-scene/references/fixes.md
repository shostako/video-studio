# 仕上げの直し

どれも無料。Veo の1本を部分的に作り直すことはできない（引き直すと8秒全部が変わる）ので、まずここで直す。

## 終わりの崩れ → 止め絵（base.cut）

1. 最後の1秒を1コマずつ見る: `vs frames clip.mp4 --out last.png --range=-1: --step 1`（素材そのものを見る）
2. 崩れる直前の「まともな最後のコマ」の番号 n を決める。画面の状態（例: ノートPCの画面が赤い）が続いているコマを選ぶ
3. scene.json の `base.cut` を `(n + 1) / 素材のfps` にする（24fps で n=186 なら 7.7917）
4. 止まっている間も重ね表示（記号の脈打ち、光）は動くので、止まったように見えにくい

## セリフの一部を消す（audio_cut）

1. 消したい音の候補の開始点を何通りか作る（文字起こしの時刻は 0.1秒ほど遅れることがある）:
   `for s in 1.36 1.40 1.44 1.48; do vs audio_cut clip.mp4 cut_$s.wav --cut $s:1.86; done`
2. それぞれを2つの耳に通す: `vs ear cut_1.48.wav --dur 2.5 --expect "通るの" --repeat 3`
3. 「消したい音が消え（--expect が含まれない）、残したい音が残る」いちばん遅い開始点を選ぶ。早すぎると前の音まで欠ける（「通る」→「通」）
4. Gemini の判定が割れる境目（3回中2回など）は、0.02秒早めて全会一致になる点を取る
5. scene.json の `base.audio` にその wav を指定。吹き出しの文言も直す
- 口の動きは消せない（「の」を言う口の動きは残る）。気になるなら Veo で引き直す
- **Whisper の語ごとの時刻は 0.1〜0.3 秒ずれる**（語の後ろの無音まで含めて長めに出る）。候補の範囲は、声の大きさから取った「声の区間」（10ms ごとの音量で無音に挟まれた塊）で決める。語尾の「て」「と」は独立した短い塊になっていることが多く、その塊をそのまま消せばよい（2026-10-12 の射出圧縮成形の解説: 8カットで余計な語22か所）
- 消す範囲の中は全音域を消す（`--band 20:20000`）。声の音域だけ消す既定では、Gemini が残りの高い音から「ね」を聞き取ることがあった。静かな部屋の音なら、0.3〜0.6 秒の無音は気にならない
- 判定は短い窓（残す語の少し前〜消す範囲の後ろ）で行い、遅い候補から順に試す。判定の文字列は「残す語」と「残す語＋余計な語」で作る。次の語の頭とつながって誤判定することがある（「ったら」＋「バルブ」→「ったらば」）ので、落ちた候補は書き起こしの中身を見る
- 耳の癖が違う: Gemini は文脈で語を補う、Whisper は窓の終わりで文を作り足す（「〜することができる」など）。片方で決めたら、もう片方で全体を通して確かめる。Gemini が使えないとき（支払いの上限など）は Whisper の書き起こしを pykakasi でひらがなにして判定できる

## ffmpeg で手作業でつないだ動画が開けない

xfade（重ねて溶かす）は、出力の色の形式を yuv444p にすることがある。h264 の High 4:4:4 になって、Windows の標準の再生ソフトで開けない（2026-10-12 実例）。`xfade=...,format=yuv420p` のように溶かした後ろで形式を戻すか、`-pix_fmt yuv420p` を付ける。置く前に `ffprobe -select_streams v -show_entries stream=pix_fmt` で yuv420p か確かめる。

## 細い線の消し残り（line_fix）

Veo で口を小さくすぼめたコマに、前の口の線が横一文字に残ることがある。

1. 素材の口元を1コマずつ拡大して、直すコマを決める: `vs frames clip.mp4 --out mouth.png --range 0.5:2 --step 1 --crop 545,235,95,55 --width 240`
   （crop は素材の座標。口の位置は顔の絵から見積もる）
2. 直すのは「開いた口の横に線が重なっている」コマだけ。しゃべって横に広がった口、閉じかけの口（線が口そのもの）は入れない
3. `vs line_fix clip.mp4 clip_fixed.mp4 --roi 548,248,620,278 --frames 14-20,25-29,31-37 --preview ba.png`
4. `ba.png`（左が前、右が後）を Read で見る。口を削ったコマは --frames から外す。線が残るコマは --delta を下げる（9→7）、斜めの線が残るなら --ratio を下げる（1.5→1.2）。顎や鼻を拾うなら --roi を口に寄せて狭める
5. scene.json の `base.src` を直した動画に替えて書き出し直す

## 勝手に描かれた物を塗り戻す（蓋の裏に画面、浮いた文字など）

Veo（Flow も同じ）は「画面を見ている」話だと、こちらを向いた蓋の裏に画面を描いたり、意味のない文字を浮かべたりする。カメラが止まっていて、その物が動かない間なら、まともなコマから塗り戻せる。見本は `assets/examples/git_blame_flow/fix_lid.py`（写して数字を直す）。

1. **範囲を決める**: 物の中の平均の差を、まともなコマ（崩れる前）と比べて、崩れ始めのコマを数で出す。文字は、出る場所の四角の中で、背景と違う画素の数を数える
2. **四隅を読む**: 細かい格子を描いた拡大を Read で見て、物の四隅を読む（20px 格子、太線は 100px ごと）
3. **動かない間**: まともなコマの同じ場所を、四角（少し太らせる）に貼る。**肌は残す**。ただしコードの色の点を拾わないよう、塊の大きさで選ぶ（150px 以上）。腕は物の後ろに回るので消えてよい（正しい前後関係になる）
4. **動く間**（閉じる途中など）: コマごとに四隅を読み、まともな物を射影変換（`getPerspectiveTransform`）で貼る
5. **周りの照り返し・溶け残り**: 物が無くなった後のコマを背景の板にする。コマごとに、物から離れた背景の帯で明るさの差（中央値）を合わせ、縁は60pxかけてなだらかにして貼る。板の明るさを合わせないと四角い跡が出る。参考のコマの髪や肌の端は背景に似ているので、背景の判定は細らせて使う
6. 全コマを書き出して見る（0.25秒おき、物のまわりを切り出して）。四角い跡、髪の線の幽霊、肌色のしみが無いか

## Veo で引き直すときの手
- 指示文の言い回しを変える／必須行（涙なし・文字なし）を確かめる
- fast にして --neg を使う
- 最後の絵の指定（--last）を外す
- 出来事を減らして最後の1秒に余白を作る
- 場面を2本に分ける（4秒×2）。つなぎ目には同じ静止画を置く

# H3 で素材を作る（この PC、無料）

MiniMax H3（2026-08 公開の動画モデル）を、Windows 側の ComfyUI で動かす。最初の絵から映像と声（日本語可）を同時に作る。費用は電気代だけ。

## 使いどころ

| | Veo（`vs veo`） | H3（`vs h3`） |
|---|---|---|
| 費用 | 8秒 $0.40（lite）〜 | 0円 |
| 時間 | 数分 | 8秒で約6分半、5秒で約3分（RTX 5070 Laptop 8GB の実測） |
| 画質 | 720p / 1080p | 864x480（0.4MP） |
| 長さ | 4 / 6 / 8 秒 | 4〜15 秒（24fps、17n+5 コマにそろう） |
| 声 | セリフ＋効果音 | セリフ＋効果音（日本語の台詞4つが書き起こしで一致した） |
| 1日の上限 | あり（lite 約17回） | なし（PC が動いている間） |

画質で Veo、本数と試行錯誤で H3。**まず H3 で芝居と台詞を詰め、気に入った指示文だけ Veo で仕上げる**使い方もできる。

## 実行

```bash
vs h3 --prompt-file prompt.txt --first start.png --seconds 8 --name Monday_Deploy
```
- 最初の絵は縦横比が違えば端の色を伸ばして合わせる（veo と同じ。控えは作業フォルダに `_first.png`・`_pad.json`）
- `--last end.png` で最後の絵も指定できる（未検証）
- `--quality` で 20 ステップ（既定は turbo の 8 ステップ）。約 2.5 倍かかる（未計測）
- `--mp 0.4`（864x480）が既定。上げると 8GB では遅いか落ちる（0.98MP の 1344x768 が H3 の本来の大きさ）
- `--seed` を変えると別の演技になる。指示どおりの1本が出るまで種を変えて回せるのが H3 の強み
- 1本目はモデルの読み込みで 1〜2 分余計にかかる。サーバーは終わっても残す。VRAM を空けたいときは `vs h3 --server free`、止めるなら `vs h3 --server stop`（vs が起動したものだけ止める）
- 終了コード 8 はメモリ不足。`--seconds` か `--mp` を下げる
- `--audio voice.wav` で声を渡せる。H3 は声を作らず、渡した声に合わせて口と体を動かす（`MiniMaxH3AddGuide` で音声を 0 コマ目から当てる）。足りない長さは無音で埋め、はみ出す分は切る。下の「声を渡す」

## 声を渡す（`--audio`）

H3 に声を作らせると、1本ごとに声色が揺れる（2026-10-26、8行の解説の1行だけ声がこもって別人に聞こえた）。アクセントも指定できない。読み上げソフトで作った声を行ごとに渡すと、声とアクセントはその音声のまま、口と体の動きだけを H3 が付ける。

- 2026-10-26 に新PC で確かめた: 4行目（8.7 秒）で、出てきた声の高さが元の音声と同じ（204Hz と 200Hz）、口は「お」「い」「あ」の形を出し、喋り終わると閉じた。かかった時間は声を作らせるときと同じ（約7分）
- 指示文はそのままでよい（台詞の行も残す。台詞が分かると口の形が合いやすいと見ている。外しての比較はしていない）

## 指示文

Veo の型（references/veo.md）がそのまま通る。H3 に特有のこと:

- **演技が大きくなる。** 頭を抱える・叫ぶ・目をつぶる、と顔が元の絵から崩れるくらい暴れる。元の顔を保ちたいときは「演技の調子」の段落を入れる。2026-10-12 に下の段落を足したら、頭を抱えて叫ぶ場面が「片手をこめかみに当てて目を細める」に収まった（台詞4つはそのまま出た）:
  ```
  Acting style: understated, deadpan and cool. Her face keeps the same calm, composed, pretty features as in the first frame the whole time; expressions change only slightly (a small smirk, slightly widened eyes, a mild frown). Her mouth opens only a little when she speaks. Small, controlled movements; she stays seated and does not flail, jump or thrash.
  ```
- 声の調子も同じ所で抑える（`speaking Japanese calmly`、`low, dry` など）。抑えない指示文だと叫び声になる
- **光の色がキャラに回る。** 「赤い光」は服や顔まで赤く染めた（セーターが後半ずっと赤茶）。光はキャラから離れた所（画面の中だけ）と書くか、重ね表示（compose の glow）に回す
- 最後の動作は落ちやすい（「画面を指さす」が「拳を握って睨む」になった）。大事な動作は前半に置く
- 「文字を出さない」「涙なし」の行は Veo と同じく入れる
- 書き方は自由文で通る。テンプレートの例は `SHOT 1:` `Audio:` の形
- 実例: `assets/examples/deploy_h3/`（控えめな演技の指示文と、ターミナル・吹き出しを重ねた scene.json。H3 の 864x480 を Veo 版と同じ大きさに置く rect は `[-462, 0, 1944, 1080]`）

## 確かめる

Veo と同じ（SKILL.md の Critical）。特に:
- 顔が元の絵から離れていないか（暴れた回は、顔が別人に見えるコマが出る）
- 光や色が服・肌に回っていないか
- 台詞は `vs ear` で聞き取らせる。私は音を聞けないので、最後はユーザーの耳で

## 入れ方（機体ごとに初回だけ。新PC は 2026-10-12 に済み）

1. ComfyUI portable（NVIDIA 版、cu130）を `C:\ComfyUI\` に展開する。`https://github.com/Comfy-Org/ComfyUI/releases` の `ComfyUI_windows_portable_nvidia.7z`。展開は Windows の `tar.exe -xf` で通る
2. `https://huggingface.co/Comfy-Org/MiniMax-H3` から次を `ComfyUI\models\` の下へ（計 約 42GB）:
   - `diffusion_models/minimax_h3_fl2va_pruned_int8_convrot.safetensors`（21GB）
   - `text_encoders/qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors`（15.7GB）
   - `vae/minimax_h3_video_vae_int8_convrot.safetensors`、`vae/minimax_h3_audio_vae_fp32.safetensors`
   - `loras/minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors`
3. `vs h3 --server start` で起動を確かめる

置き場を変えたときは環境変数 `VS_COMFY_ROOT`（既定 `/mnt/c/ComfyUI/ComfyUI_windows_portable`）。

## 仕組み（壊れたとき）

- WSL から Windows の `127.0.0.1:8188` には届かない。そこで `h3.py`（WSL）がグラフを JSON に書き、`h3_client.py` を ComfyUI 同梱の Python（Windows）で動かして HTTP を受け持たせる。係とジョブの置き場は `C:\ComfyUI\vs\`
- サーバーの起動オプションは `--disable-pinned-memory --disable-async-offload --reserve-vram 1`。Blackwell＋Windows で H3 の VAE デコードが落ちる既知の問題（ComfyUI issue #15337）の回避。手で起動するなら `C:\ComfyUI\ComfyUI_windows_portable\run_h3_8gb.bat`
- サーバーのログは `C:\ComfyUI\ComfyUI_windows_portable\vs_server.log`
- グラフはテンプレート `video_minimax_h3_i2v`（Comfy-Org/workflow_templates）の中身を API 形式に開いたもの。ComfyUI を更新してノードの入力名が変わると「受け付けられなかった」（終了コード 2）になる。`/object_info` で入力名を見直す
- WSL 側に ComfyUI を置かない理由: 8GB の肝の省メモリ機能（Dynamic VRAM）が WSL では使えず、WSL のメモリ上限も既定 15GB で足りない

## ライセンス

MiniMax H3 の利用条件: 日本は可。年商 US$20M 以下は許可不要。**商用製品に使うなら「MiniMax H3」の表示が要る**（会社の資料・製品には載せない前提で導入した）。出力を他のモデルの学習に使えない。

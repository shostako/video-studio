# 落とし穴と直し方

2026-10-12 の射出圧縮成形の解説（69秒）を作った時に実際に出たもの。

## 声

- 動画生成モデル（Veo・Seedance）の声は使わない。8秒ごとに声が作り直されて別人になる／専門用語を読み違える／台詞を落とす。声は Irodori-TTS で台本全体を先に作る（今回の動画はこの失敗から方式を変えた）。
- Irodori は漢字の読みに弱い（金型→きんがた、型締力→かたしめ、可動側→かどうそく、開く→あく）。**正しい読みと誤りが同じ漢字になる語は、聞き取り（Whisper）の書き起こしで見逃す**。合成に渡す文（`say`）だけひらがなにする。`vm voice synth` の「台本との一致」が 0.9 を割った行を直す。
- 声の高さ（F0）は行ごとにぶれる。最初に作った行を手本（`ref`）にして残りを読ませると、全行の高さがそろう（今回 208〜222Hz に収まった）。冒頭の行は高く出やすいので、乱数の種を何本か変えて選ぶ。
- 「ストローク」「奥まで届かない」などは Veo の音声フィルタで止まる語だった。Irodori にはこの制約がない。

## 絵（/img）

- 口・目の差分を描かせると、**絵全体が元から数%の拡大・数画素のずれ**で返ってくる。切り抜きの位置合わせは口・目の外側だけを手がかりにする（口に合わせると閉じた口に歪む）。`vm parts` はこれを実装済み。
- 範囲の自動検出（差分の合意）は、口より髪の差分が大きくて外れた。口・目の範囲は人（or 私）が home で測って、他の姿勢へ顔の重ね合わせで写す。
- 姿勢の絵は大きさが姿勢ごとに最大5%違った（両手を開く）。足の位置をそろえるだけでなく、靴底〜頭頂の高さで大きさもそろえる。

## 軸足そろえと画面の端

- **軸足をそろえて絵を動かすと、指先が画面の外に出る**（原画では71画素の余白があった手が、60画素右へ動き5%拡大されて切れた）。左右に白い余白（`pad`）を足した広い画面に置く。出力動画の幅が広くなるので、重ねる時は幅を計算して置く（`vm overlay` が自動）。
- 靴の位置は、そろえる前は姿勢で左右約70・上下約45画素動いていた。そろえた後は全編で左右5・上下7画素（息づかい分）。

## 口の大きさ

- 口を声の大きさに忠実に開けると「大げさ」に見える。小さい開き（m7）を足し、声が中くらいの所は m1/m7 で済ませ、半開き（m2）は強めの山、大きい開き（m3）は強い「あ」だけにした。それでも大きく見えるなら `--mouth-scale 0.8`。
- 形が変わるコマは前後を半々に溶かす（1コマ）。1コマだけの形は前後の形に揃える（ちらつき防止）。

## 重ね

- 白い背景の主動画（3Dの金型など）には `multiply`（乗算）で、白が透けて境目が出ない。背景が白でない主動画は `alpha`（背景透明の webm）。
- 絵の背景は 253（真っ白でない）。ページ（`bg`）を `#fdfdfd` にそろえると枠が出ない。
- **乗算（blend=all_mode=multiply）は、両方の入力を同じ形式（gbrp）にそろえてから**。yuv420p どうしを直接乗算すると、色が緑一色にずれる（2026-10-12 に `vm overlay` で出て直した）。`vm overlay` は対応済み。
- ffmpeg の `xfade` は出力を yuv444p にして Windows の標準プレーヤーで開けなくなることがある。`format=yuv420p` を後ろに付ける。

## 費用の見方

動画生成サービス（Hedra の Character 3・Kling Avatar、Seedance、Veo）で同じことをやると、60秒で $3〜$20 かかり、作り直しのたびに増える。今回は先に $50 以上を使ってからこの方式に着いた。**設定を変えたら短い1本で確かめてから全部に広げる**。

## 透明にする（alpha）

- 白い背景を透明にする処理（`lib.matte`）は、(1) 画面の端とつながる白を背景にする、(2) 顔の箱の外の孤立した白（毛束に囲まれたすき間）も背景にする、(3) 箱の中の白は白目・歯なので守る（ただし大きすぎる白は背景）、(4) 黒い物（髪・靴）の縁は、暗さから「背景の白とのまざり具合」を割り戻す、(5) 取り残された小さな白は、周りが黒い毛なら消す、の順。
- 実測（暗い背景に重ねた全身の1コマ）で、すき間の白が7か所残った。肌・髪・耳に接した細長い白は、「髪のハイライト」と「背景」を画像だけでは見分けにくい。**完全に抜くには、絵を描かせる段階で背景を単色（緑など）にして色で抜く**のが確実（未検証。次に作るとき `mascot.description` に背景色を書いて試す）。
- 足元の影は黒の半透明で別に持たせて重ねる（透明版では影が色つき背景になじむ）。
- 白い背景の主動画には `--mode multiply`（`render --mode white` の出力）が安全で、境目も出ない。

## 身振りが出ていないのに気づけない（2026-10-31）

- 頭の動き（`config.head`）が 2 回ある解説動画で、1 回目の終わりから 2 回目の始まりまで（34〜95 秒）頭の列の home の絵が出続け、その間の身振り 23 件が全部消えた。書き出しは正常に終わり、エラーも出なかった。気づいたのは「指振りとつまむの Wan が作られていない」から。Wan の列は最初に引いた時に作るので、身振りが出ないと Wan も呼ばれない。原因は `lib.head_pos` が要所の最初から最後までを全部「頭の動きの中」として返していたこと（PR #48 で直した）。
- 教訓: 書き出しが終わったこと・ログにエラーが無いことは、身振りが出た証拠にならない。**下見（`vm render --check-only --strict`）で切り替えが全部出るかを書き出す前に見て、書き出した後は `vm check --strict` で画素が動いたかを測る**。どちらも問題があれば終了コード 3 で止まる。
- 画素で測るときは顔を外す。視線は体の切り替えに合わせて先に動くので、身振りが消えていても目だけが変わり、画面全体の変化（0.36%）が指を 1 本増やす本物の切り替え（0.27%）より大きく出た。

## 会釈しながら話すと口が止まる（2026-10-31）

- 会釈の姿勢（`nod`）は `face: false`（口の部品が無い）。台本で、最後の台詞「それだけ覚えておけばいい」や冒頭の「…方を説明する」の途中に会釈を置いたら、顔ははっきり見えるのに口が動かず不自然だった（ユーザーの指摘）。指を振る片側（`wag_l`）も同じく `face: false` で、0.1〜0.4 秒口が止まっていた。
- 直し方: 会釈は話していない所に置く（話し終わりの後に時間が無ければ会釈をやめる）。`wag_l` は home と顔が同じなので `vm parts --borrow home wag_l`（顔の合い 0.998）で口を持たせた。
- 下見（`vm render --check-only --strict`）の口の検査が、口の部品の無い姿勢で 0.2 秒以上話している所を問題にする。

## 長い動画の終わりで口が声より先に動く（2026-11-01）

- 280 秒の解説（60fps）の最後の台詞「そこだけ押さえておけばいい」で、声が出ている 277.3〜278.0 秒の間、口が閉じたままだった。原因は口の大きさを測る声の位置。コマの頭を `SR // FPS`（16000 Hz・60fps で 266.67 を 266 に切り捨て）の歩幅で進めていたので、後ろのコマほど早い時刻の声を読み、終わりで 0.69 秒ずれた（30fps でも 280 秒で 0.17 秒）。母音の時刻（語の聞き取り）は正しいので、「母音はあるが声が無い」コマで口が閉じ、ずれた先で開いた。
- 直し方: `lib.frame_levels` でコマの頭を `round(f * SR / FPS)` にした。screen-explainer の compose.py と video-scene の例も同じ。
- 教訓: 短い試しの動画ではずれが小さく（10 秒で 0.03 秒）見えない。長い動画は最後の台詞の口元を数コマ並べて、声の出だしと口の開きが合っているかを見る。

## 英字・数字の語で口が閉じる（2026-11-01）

- 凜の解説 3 本で、声が出ているのに口が閉じている所（0.2 秒以上）が、設備メンテナンス費で 47 か所・13 秒、電気代で 26 か所・8 秒、cad-viewer で 11 か所・3 秒あった。cad-viewer は冒頭の「CAD Viewer の」0.8 秒がまるごと閉じていた。
- 原因 1: 音量式の口パクは聞き取りの語をひらがなにして母音を取る。語が「CAD」「IGES」「100」「%」「×」のままだと、かなが無く母音が付かない（台本の `say` にカタカナで書いていても、聞き取りの語は英字で出る）。かなの無い語は母音「あ」にした（`lib.word_hira`）。
- 原因 2: 聞き取りの語の時刻は声より短めに出る。文の頭で語の始まりが声より 0.3 秒ほど遅く、語の間でも声が出ているのに母音が無いコマがあった。語の端から 0.4 秒以内で声が出ているコマは、近い語の母音にした（`lib.fill_vowel_gaps`）。
- events の語の位置探し（音の並び）は今までどおり、かなの語だけで作る（身振りの時刻を変えない）。
- 下見の口の検査に「声が出ているのに口が閉じている所」を足した。会釈の件も前の口のずれも、目で見て気づくまで分からなかった。モーラ式は台本の区切りに閉じを割り付けるので知らせるだけにした。

## 完成動画の測定で小さい切り替えが「弱い」に落ちる（2026-11-01）

- 凜の設備メンテナンス費の完成動画（全身を高さ 560px で重ね、測る範囲 448x644）で、指を 1 本増やす切り替え（count_2→count_3）が顔の外の変化 0.100% になり、基準（0.10%）ちょうどで「弱い」と出た。透明の webm の段階では「動いた」。測るときに高さ 360 に縮めていたので、小さい指の変化が平均されて薄まっていた。
- 測る高さを 720 にした。いちばん小さい切り替えは 0.21% に上がり、動いていない対照（話しているだけの区間の組を 1 つずつ外して覆いを作り、外した組を測る）は 360・540・720 のどれでも最大 0.012% で変わらなかった。

## 作り置きが別の場所で使えない（2026-11-01）

- Wan の切り替えと RIFE の列の作り置きは、元の絵の「名前・更新時刻・大きさ」で、作り直すかを決めていた。作業フォルダを写す（zip で別の PC に運ぶ）と更新時刻が変わり、作り置きがあるのに作り直そうとする。Wan の無い PC（旧PC）では ComfyUI に届かず止まる（凜の cad を写して確かめた）。
- 共有の作り置き（凜の 3 本の `b-shared/ib_wan`）でも、同じ部品の更新時刻がフォルダごとに違い、書き出すたびに後処理の RIFE をやり直していた。
- 判定をファイルの中身の印（md5）にした（`lib.file_sig`・`stamp_ok`）。前の形の stamp は、更新時刻が合えばその場で中身の印に書き換えるので、作り置きは捨てない。パックにする前に一度書き出す（下見ではなく本番）と、使った組の stamp が中身の印になる。

## 行の声の終わりのプツッという雑音（2026-11-01）

- 旧PC の「Claude Code デスクトップの使い方」で、ユーザーが「ショートカットの一覧…」の少し前にプツッという雑音を聞き取った。Irodori の行の声（l11.wav）の最後の 0.04 秒に、読み終えて 0.36 秒黙ったあとのピーク 0.56 の音があり、ファイルの端で切れていた。同じ文・seed・手本なら同じ音が毎回出る。凜の 3 本のときは気づいた所を手で 30 ミリ秒無音にしただけで、道具には入れていなかった。
- `vm voice master` が各行を調べ、声が終わって 0.25 秒以上黙ったあとに、0.1 秒以内の短い音がファイルの端で切れていれば、そこを無音にした写し（`voice/_clean/l<n>.wav`）で master を組む（`lib.tail_blip`）。長さは変えないので行の時刻はずれない。消したときは行と秒と大きさを出す。行の途中の読点の間（黙ったあとに語が続き、端の前に終わる）は端で切れていないので触らない。
